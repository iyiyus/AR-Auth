# 后端独立运行时部署 H5

后端在同一域名、同一路径按浏览器 `User-Agent` 自动选择 PC 或 H5 页面，不新增 `/h5` 页面入口。iPhone、iPad、iPod、Android、Mobile、Windows Phone 等移动端标识使用 H5；普通桌面浏览器使用 PC。`/install` 及其子路径始终使用 PC，以保留完整安装流程。管理登录 `/admin` 与其他管理页面同样按浏览器标识分流。iPad 使用桌面模式且浏览器标识只包含 Macintosh 时，会按 PC 处理；严格仅按浏览器标识分流无法可靠区分这种情况。

移动用户、代理端提供独立导航与登录，业务子页沿用现有购买、授权、账户、实名、工单等调用链。管理端覆盖概览、授权查询/启停、工单回复/关闭/重开，复杂配置提示在电脑端操作。移动登录页不复刻 PC 公开首页模板及公开授权、代理、目标查询。

## 构建与目录

H5 的 Vite 配置必须使用 `base: '/'`、`build.assetsDir: 'h5-assets'`。构建产物上传到 `AUTO_PRO_DATA_DIR/h5`，也可通过 `AUTO_PRO_H5_DIR` 指定独立目录。上传的是构建目录中的内容，而不是把整个 `dist` 目录再套一层：

- `h5/index.html`
- `h5/h5-assets/<构建生成的 JS、CSS、图片与字体>`

运行账号需要对根目录、资源目录拥有遍历权限，并对文件拥有读取权限。仅上传可信构建产物；H5 和 PC 静态目录都不应混入配置、私钥、数据库备份或源码。H5 公共资源应被打包到 `h5-assets`，而不是与 PC 共用根目录文件名。默认数据目录由现有后端配置确定；建议生产环境显式设置 `AUTO_PRO_DATA_DIR`。

## 本地构建与预览

在本机 `h5/` 目录执行 `pnpm install --frozen-lockfile`，再执行 `pnpm build`。工程复用相邻 `frontend/` 的业务组件与 API 类型，因此构建时应保留完整仓库并安装 PC 前端依赖；部署时只需要 `h5/dist/` 中的文件。

本地继续使用 `frontend/` 原来的开发命令和端口 3006，电脑与手机访问同一 URL，由开发入口按浏览器标识返回 PC 或 `h5/dist/`。API 保留原有代理，安装页面保留 PC。H5 不启动额外 HTTP 服务；修改后重新构建并刷新，或在 `h5/` 执行 `pnpm dev` 监测文件持续构建，该进程不监听端口。H5 入口缺失时回退 PC，构建更新后无需重启开发服务。这部分开发配置不参与 PC 生产构建；生产仍由 Go 后端在原服务端口分流。

H5 源码、依赖、测试和构建产物均被根目录 `/h5/` 忽略，不进入 Git 或 Gitee。请另行备份本机 H5 工程；普通 Git 克隆无法恢复这部分源码。仓库中的后端分流代码与本文档可以正常提交。

## 热部署与回退

后端每次请求重新打开磁盘文件，不缓存 H5 是否存在，后续上传、替换、删除 H5 均无需重启。环境变量变更仍需重启进程。

首次使用需要先更新包含 H5 分流能力的后端并重启一次；以后只上传 H5 产物即可。当前在线更新流程只切换后端与 PC 前端，默认数据目录下独立的 `h5/` 不参与切换。自定义 `AUTO_PRO_H5_DIR` 应放在 PC `current`、`releases` 和更新暂存目录之外，避免发布清理影响它。使用 systemd 时应将该变量持久写入服务配置，而不是仅设置在一次启动的终端中。

推荐发布顺序：先上传带内容哈希的新 `h5-assets` 文件，再用临时文件原子替换 `index.html`。旧资源应保留一段时间，避免已打开页面请求旧文件时发生 404。首次上传期间保持 `index.html` 不存在，全部资源就绪后再发布入口。

H5 入口不存在、为空、不可读、是目录或目录树内软链时，移动端页面回退到现有 PC 磁盘入口；PC 磁盘入口不可用则使用后端内嵌 PC。后端无法可靠识别非空但尚未上传完成的 HTML，因此应遵循入口最后发布、原子替换的顺序。回滚时移走 H5 `index.html` 即可立即恢复 PC；保留旧资源可兼容仍打开的 H5 页面。

## 资源与业务路由边界

- `/h5-assets/*` 始终只读取 H5 目录，桌面与手机结果一致。请求的路径包含 `h5-assets/`，因此磁盘文件实际位于 `h5/h5-assets/*`。
- PC 的 `/assets/*` 和根目录公共文件始终读取 PC 构建，不因移动端浏览器标识而切换。PC 磁盘入口存在时，其资源来自 PC 磁盘目录；否则使用内嵌 PC 资源。
- 缺失资源、目录、非法路径、敏感文件和目录树内软链返回 404，不回退到单页应用入口。部署根目录可以是管理员维护的软链，根目录内的软链文件或目录会被拒绝。
- `/api`、`/realname-face` 和 `/admin/app-store` 的真实业务路由保持优先，包括支付回调；其未匹配请求也不会返回 H5 页面。
- 页面响应包含 `Vary: User-Agent` 与 `Cache-Control: no-cache`。资源响应不按浏览器标识变化。缓存代理应遵循页面响应头，或直接跳过页面缓存。

## 反向代理注意事项

该功能只对实际到达 Go 后端的请求生效。如果 Nginx 或其他 Web 服务器先执行 `try_files ... /index.html`、直接读取 PC 根目录，浏览器页面将绕过后端分流。需要将页面与 `/h5-assets/*` 请求代理到后端，并保留 `User-Agent`。缺失资源不得由代理改写为 `index.html`；禁止将服务数据目录整体作为公开静态目录。

## 验收

分别使用桌面浏览器和手机浏览器访问 `/`、`/admin` 与已有用户/代理/管理页面路径：桌面返回 PC，手机在 H5 入口就绪时返回 H5。手机访问 `/install` 应仍返回 PC。对同一个 `/h5-assets/<真实文件>` 改变浏览器标识，应返回同一个 H5 资源；不存在的 H5 与 PC 资源均应为 404。

移走 `h5/index.html` 后，无需重启手机页面即应回退 PC；重新发布入口后即恢复 H5。检查页面响应中的 `Vary` 和 `Cache-Control`，并在生产反向代理或 CDN 环境再验证一次，避免代理覆盖后端行为。
